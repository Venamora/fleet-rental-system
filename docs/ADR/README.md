# ADR Directory

Architecture Decision Records capture significant, approved technical decisions, their alternatives, consequences, and status. ADRs are distinct from the PRD (what is required), architecture overview (approved boundaries), agents (responsibilities), skills (procedures), and MCP (external tool integrations).

No numbered ADRs are authored during the current PRD/workflow/skills documentation phase. The ADR phase is phase 4, after the phase 3 Architecture gate has been explicitly approved. Then create a numbered ADR only for an approved decision that materially affects the system; link it from the architecture record and keep superseded decisions visible. Do not make or record architecture or technical decisions now; implementation (phase 7) remains blocked until the preceding gates are passed.
